# Mercury 프론트 QA 시나리오 가이드

부동산 경매 앱 Mercury(iOS / SwiftUI)의 **프론트엔드 QA 시나리오** 작성 기준 문서.
데이터 파트(API 응답·값 정확성)는 별도 시트로 분리한다.

## 산출물

- `docs/qa/QA_프론트_시나리오_2026-06-29.csv` — 마스터 시트
- UTF-8 **BOM 포함**으로 저장 (Google Sheets / Excel 한글 깨짐 방지)
- Google Sheets: `파일 → 가져오기 → 업로드`로 불러오기

## 컬럼 스키마

| 컬럼 | 설명 |
|---|---|
| ID | `FE-{모듈코드}-{3자리}` (예: FE-AH-001) |
| 대분류 | 모듈/기능 영역 (예: 경매홈) |
| 중분류(화면) | 화면 단위 (예: 매물리스트) |
| 소분류(기능) | 기능 단위 (예: 무한스크롤) |
| 시나리오 | 검증하려는 동작 한 줄 요약 |
| 사전조건 | 테스트 전 갖춰야 할 상태 (로그인 여부, 데이터 조건 등) |
| 테스트절차 | 단계별 조작 (1. … 2. …) |
| 기대결과 | 정상 동작 시 기대되는 UI/동작 |
| 유형 | 정상 / 예외 / 경계 |
| 우선순위 | P0 / P1 / P2 |
| 결과 | 테스터 기입 (Pass/Fail) |
| 비고 | 버그 링크, 데이터파트 연계 태그 등 |

## 우선순위 기준

- **P0** — 핵심 동선, 크래시/진입 불가급. 실패 시 출시 블로커.
- **P1** — 주요 기능. 실패 시 사용성 저하.
- **P2** — 부가 기능, 예외/경계 케이스.

## 유형 기준

- **정상** — 의도된 정상 입력/흐름.
- **예외** — 에러·실패·비정상 입력(네트워크 끊김, 권한 거부, 빈 데이터 등).
- **경계** — 한계값/엣지(긴 텍스트, 0건, 중복 탭, 토큰 만료 등).

## 4축 패턴 카탈로그

모든 화면에 아래 4축을 기계적으로 적용해 시나리오를 도출한다.

- **상태축**: 초기 로딩 · 성공(데이터 有) · 빈 상태(empty) · 에러(네트워크/서버) · 권한 거부 · 비로그인
- **상호작용축**: 탭(버튼/셀) · 스크롤(무한·당겨 새로고침) · 필터/정렬 적용·초기화 · 텍스트 입력·검증 · 토글(관심 등) · 바텀시트/모달 열기·닫기 · 페이저/탭 전환
- **전환축**: 진입(onAppear) · 이탈/복귀 시 상태 보존 · push/pop · present/dismiss(fullScreen) · 딥링크/공유 진입 · 백그라운드→포그라운드 복귀
- **엣지축**: 네트워크 끊김/지연 · 빈 데이터 · 중복 탭(디바운스) · 긴 텍스트/오버플로우 · 다크모드(해당 시) · 토큰 만료·재로그인

## 프론트 / 데이터 경계 규칙

- **프론트(이 시트)**: UI 렌더링, 상호작용, 네비게이션, 로딩/빈/에러 상태의 **표시 여부**, 입력 검증, 상태 보존.
- **데이터(별도 시트)**: 경매금액·날짜·매핑값 등 **값의 정확성**, API 응답/에러코드, 서버 비즈니스 로직.
- **회색지대**(예: 필터 결과): "필터 UI 동작과 결과 반영 여부"는 프론트, "결과 데이터가 조건에 맞는지"는 데이터.
- 값 정확성이 얽힌 케이스는 비고에 **`데이터파트 연계`** 태그를 남겨 누락을 방지한다.
